## 3. Un turno de conversación

```mermaid
flowchart LR
  S([START]) --> L[load: relee el caso]
  L -->|etapa terminal| F[finish: mensaje final] --> E([END])
  L -->|ESCALATED| AN[announce] --> AW[await_advisor<br/>interrupt + checkpoint] --> L
  L -->|topes de pasos o violaciones| LM[limit: escala o avisa]
  L -->|etapa activa| ACT[act: política elige acción<br/>lista blanca por etapa]
  ACT -->|tool| EXE[ejecutor] --> L
  ACT -->|reply| E
  LM --> L
```

`act` pide a la política **una** acción; si es una tool la ejecuta por el
ejecutor y **vuelve a `load`**, que relee el caso: la etapa la dicta el
dominio.

## 4. Estados del caso

```mermaid
stateDiagram-v2
  [*] --> ELIGIBILITY
  ELIGIBILITY --> REJECTED: auto no es del cliente o tiene adeudos
  ELIGIBILITY --> PROFILING: elegible (con o sin segunda llave)
  PROFILING --> DECLINED: perfil no aprobado
  PROFILING --> ESCALATED: expediente delgado o sin score
  PROFILING --> SIMULATION: perfil aprobado
  SIMULATION --> DOCUMENTS: el cliente elige un plazo que cabe
  DOCUMENTS --> NEEDS_CORRECTION: mismatch o baja confianza
  NEEDS_CORRECTION --> DOCUMENTS: el cliente reenvía
  DOCUMENTS --> SIMULATION: el ingreso verificado invalida la cuota
  DOCUMENTS --> ESCALATED: inconsistencia grave
  ESCALATED --> PROFILING: el asesor reanuda
  ESCALATED --> DOCUMENTS: el asesor reanuda
  ESCALATED --> REJECTED: el asesor rechaza
  ESCALATED --> DECLINED: el asesor declina
  DOCUMENTS --> READY_FOR_LENDER: gate OK (reevaluado en la tool)
  READY_FOR_LENDER --> [*]
  REJECTED --> [*]
  DECLINED --> [*]
```

Desde `ESCALATED` solo se reanuda **donde se escaló** (`escalated_from`) o se
cierra. Las etapas terminales no tienen salidas.

## 5. Pipeline del ejecutor

```mermaid
sequenceDiagram
  participant P as Política o asesor
  participant E as Ejecutor
  participant T as Tool / dominio
  participant R as Repositorio
  participant A as Bitácora
  P->>E: call(principal, sesión, tool, args)
  E->>E: 1 entrada válida (extra=forbid)
  E->>E: 2 el principal tiene el scope
  E->>R: 3 cargar caso · case_id == sesión
  E->>E: 4 idempotencia (ventana de versiones)
  alt reintento
    E-->>P: resultado guardado
  else nueva
    E->>E: 5 etapa permitida · versión esperada
    E->>T: 6 ejecutar
    T-->>E: Outcome (salida + caso nuevo)
    E->>E: 6b validar salida contra su modelo
    E->>R: 7 save(caso, expected_version)
    R-->>E: ok / StaleVersion
  end
  E->>A: 8 evento: hashes, resultado, motivos, etapa resultante
  E-->>P: ToolResult
```

## 6. El gate (`mark_ready_for_lender`)

```mermaid
flowchart TB
  M[mark_ready_for_lender] --> R1[Revisión documental desde cero<br/>sobre los documentos ligados]
  M --> R2[Recalcula la opción elegida<br/>y compara su hash]
  M --> R3[Elegibilidad y perfil guardados]
  R1 & R2 & R3 --> G{9 chequeos<br/>todos OK?}
  G -- sí --> OK[READY_FOR_LENDER<br/>guarda inputs_hash y rule_version]
  G -- no --> NO[Se niega: lista los bloqueos<br/>y escala la política]
```

Chequeos: `eligibility`, `profile`, `simulation_current`, `documents_present`,
`documents_valid`, `income_identity`, `ownership`, `payment_capacity`,
`no_open_corrections`.

## 8. Camino de una petición (operación y seguridad)

```mermaid
flowchart LR
  C([Cliente / canal]) --> MW[Middleware<br/>X-Correlation-ID · tope 64 KB<br/>cabeceras seguras · log sin PII]
  MW --> AU[Autenticación<br/>X-API-Key por principal]
  AU --> SS[SessionStore<br/>vence · purga · tope]
  SS --> RL[RateLimiter<br/>30 mensajes/min por sesión]
  RL --> LK[Cerrojo por caso<br/>un turno a la vez]
  LK --> AG[Grafo y política]
  AG --> EX[Ejecutor<br/>8 defensas]
  EX --> DB[(MongoDB<br/>versión optimista)]
  EX --> AUD[(Bitácora<br/>hashes, sin PII)]
  V[/verify/] --> AL[AttemptLimiter<br/>bloqueo temporal]
  ST([Arranque]) --> CV[config/validation<br/>prod no arranca si es insegura]
  CV --> RD[/ready: Mongo y bitácora escribibles/]
```

El arranque falla si la configuración es insegura o si no se puede escribir la
bitácora (ADR-0006); `/ready` repite esa comprobación en cada sondeo.
